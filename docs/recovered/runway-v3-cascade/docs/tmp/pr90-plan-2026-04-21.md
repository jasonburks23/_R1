Same orphaned-column read in two more files:
- src/lib/runway/operations-reads-health.ts:434 (getStaleProjects)
- src/lib/runway/operations-reads-pipeline.ts:95

Fix: inline compute daysSince(item.updatedAt) instead of reading
stale_days column. Matches the existing pattern in plate-summary.ts
before deletion (or wherever else in the codebase uses this idiom
— grep first).

Changes:
1. flags-detectors.ts ~line 80: replace `item.stale_days >= 14`
   with `daysSince(item.updatedAt) >= 14`. Extract or import
   daysSince helper.
2. operations-reads-health.ts:434: same swap.
3. operations-reads-pipeline.ts:95: same swap.
4. src/app/runway/page.tsx ~lines 50-71: pipe updatedAt into the
   Account.items shape so flags-detectors reads it. Adjust the

   stale-dated row + a fresh-dated row; assert only stale fires.

The projects.stale_days column stays in schema for now. Dropping

### Task 2: Merge PlateSummary into FlagsPanel

Two new detectors, deletion of old component.

Current: src/app/runway/components/plate-summary.tsx is a
top-of-board banner showing (green) retainer-renewal pills +
(red) contract-expired pills. Data logic lives in
src/lib/runway/plate-summary.ts (retainerRenewalPills,
contractExpiredPills).

Target: merge into FlagsPanel as two new WARNING-severity
categories.

Steps:
1. Add two detectors to src/lib/runway/flags-detectors.ts:
   - detectRetainerRenewals(): L1s with engagementType='retainer'
     AND contract_end within 30 days of today. Severity: WARNING.
     Message format: "Renewal: <projectName> expires <date>".
   - detectContractExpired(): Clients with contract_status='expired'
     AND >= 1 active L1 (status in in-production/not-started/blocked).
     Severity: WARNING. Message: "Contract expired: <clientName>".
2. Wire both into analyzeFlags() in flags.ts.
3. Update FlagsPanel rendering (src/app/runway/components/flags-panel.tsx)
   to handle the two new categories. Keep soft amber/red styling
   so the tone doesn't change.
4. Tests: flags-detectors.test.ts covers:
   - Positive match for retainer-renewal (contract_end today, +15d, +29d)
   - Negative match (contract_end +31d — outside window)
   - Positive match for contract-expired (expired + active L1)
   - Negative (expired + no active L1 → should NOT fire)
   - Non-retainer with contract_end near (should NOT fire renewal)
5. Delete src/app/runway/components/plate-summary.tsx.
6. Delete src/lib/runway/plate-summary.ts unless grep shows
   imports elsewhere; if so, migrate those callers.
7. Unmount PlateSummary from src/app/runway/page.tsx.
