## Why it exists

PR 88 added a field-specific `parentProjectId` empty-string → null coercion. Llama flagged this as a hidden contract: the MCP schema uses `z.string()` (allows empty strings), but one specific field silently transforms `""` to `null`. If another nullable field gets added later, a developer might miss the pattern and ship inconsistent behavior.

Proper fix: generalize at the helper boundary so ALL nullable text fields coerce `""` → `null` consistently, or explicitly opt out.

## Why it's separate (not folded into PR 89)

- Needs a caller audit across MCP tools, Slack bot, API routes before generalization
- Some callers might intentionally pass `""` as semantically distinct from `null`
- Generalizing without audit = silently breaking something 2 weeks later
- PR 89 is already at 11 commits; adding architectural refactor scope is too much
- Sequential after PR 89 merges keeps the conflict resolution simple

### Task 2: Add normalizer

In `src/lib/runway/operations-utils.ts`:

```ts
/**
 * Canonicalize nullable-string inputs. null, undefined, "", and
 * whitespace-only strings all become null. All other values pass through.
 * Used at the helper layer to ensure consistent audit + idempotency
 * behavior regardless of whether callers pass "" or null.
 */
export function normalizeNullableString(v: string | null | undefined): string | null {
  if (v == null) return null;
  return v.trim() === "" ? null : v;
}
```
